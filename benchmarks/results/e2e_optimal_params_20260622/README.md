# 历史最优参数复现与性能改进验证 (Optimal Parameters Revalidation)

**测试日期**: 2026-06-22  
**环境**: Codespace（4 vCPU, 15GB 内存, AMD EPYC 7763 虚拟化）  
**采样规范**: SPEC 7.3.2 规范化（预热 1 轮 + 正式采样 5 轮）  
**目标**: 验证历史最优参数(conn8+payload128)是否能在当前代码上复现，并对标 2026-06-20 单轮采样结果

## 背景与动机

2026-06-20 的维度对比测试发现**最优工作点为 conn8 + payload128**，吞吐 277.8k tps，P99 延迟 44.78ms（单轮采样）。

本轮测试目标：
1. 确认当前代码是否能复现该最优结果
2. 验证是否存在代码性能回归
3. 用更严谨的 SPEC 规范采样（1 预热 + 5 正式）获取更真实的均值
4. 为后续性能优化建立明确基线

## 测试参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `client_connections` | 8 | 并发 TCP 连接数 |
| `payload_bytes` | 128 | 每个任务的 Payload 大小 |
| `tasks` | 20,000 | 每轮发送的总任务数 |
| `threads` | 4 | 服务端工作线程数 |
| `queue_capacity` | 8,192 | 无锁队列容量 |

采样方式：
- 预热轮：1 轮（不计入统计）
- 正式采样：5 轮（计入统计和汇总）

## 性能改进原因分析

### 可能的积极因素

1. **代码优化积累**
   - 2026-06-20 之后的任何性能优化（如 epoll 事件处理、无锁队列调整等）
   - 或 NetworkIngress 背压机制完善

2. **编译优化**
   - 当前采样使用 Release 构建 (-O3 优化)
   - 历史可能使用了 Debug 或默认优化级别

3. **环境状态变化**
   - Codespace 此时的邻近资源占用情况更佳
   - 系统缓存预热更充分

4. **采样规范差异**
   - 历史单轮可能恰好命中优良时段
   - 本轮 5 轮均值相对不同时段的平衡结果

### 排除可能的退化因素

✓ 无内存泄漏（5 轮均通过）  
✓ 无链路丢失（每轮 20,000 帧完整入队）  
✓ 无执行器故障（5/5 轮完成 20,000 任务）  
✓ 无背压异常（无 enqueue_timeout）

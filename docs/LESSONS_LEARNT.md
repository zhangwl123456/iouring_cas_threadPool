# 经验教训

- 所有规则配置文件必须放置在 .github/copilot-instructions.md。
- 项目文档须统一放在 docs/ 目录内，并使用中文编写。
- 在进入实现前必须先锁定范围边界；当范围收敛时，应同步更新 SPEC 与 PROGRESS_LOG，避免出现“文档目标已变更但契约未收敛”的偏差。
- 当用户提出“需要解析请求”时，必须二次澄清是“消息边界切分”还是“业务语义解析”，并在 SPEC 中显式写出层级边界，防止网络层与协议层职责错位。
- 当业务参数尚不确定时，应在 SPEC 中先冻结可执行默认值（如包体估算、推送频率、补传窗口），并注明“后续可由压测与实测回填”，避免阻塞系统设计。
